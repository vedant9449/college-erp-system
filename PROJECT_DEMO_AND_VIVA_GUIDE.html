3. Where and How Is Data Stored? (Crucial Viva Concept)

Sir's Question: "Where is the data stored? In which file is it kept?"

EXACT ANSWER:
"Sir, the application does not store data in plain text or CSV files. It uses a relational database management system (RDBMS), specifically MySQL / MariaDB running locally via XAMPP on port 3306.

The database name is college_erp, containing 7 normalized relational tables:
1. users: Authentication credentials and roles.
2. students: Student demographics, roll numbers, semesters, and departments.
3. faculty: Instructor directories, designations, and salaries.
4. courses: Course catalog with foreign keys referencing faculty.
5. attendance: Daily lecture attendance records linked to students & courses.
6. exams: Assessment marks, maximum marks, and computed letter grades.
7. fees: Institutional billing ledgers, paid amounts, and due balances.

The physical data files are managed by MySQL's InnoDB storage engine at C:\xampp\mysql\data\college_erp\. We can inspect and manage all tables visually via phpMyAdmin at http://localhost/phpmyadmin."

5. Top Viva Questions & Model Answers

Q1: Why did you use PreparedStatement instead of regular Statement?

Answer: "PreparedStatement pre-compiles SQL queries on the database server, offering faster execution for repetitive calls. More importantly, it uses parameterized placeholders (?) that automatically sanitize user input, completely preventing SQL injection vulnerabilities."

Q2: What is JDBC and how does it work in your project?

Answer: "JDBC (Java Database Connectivity) is a standard Java API that bridges Java applications with relational databases. In our project, DriverManager.getConnection() establishes a TCP connection to MySQL on port 3306 using the mysql-connector-j driver jar in our lib/ directory."

Q3: What is the purpose of the DAO (Data Access Object) pattern?

Answer: "The DAO pattern decouples presentation code (Swing GUI) from persistence logic (SQL queries). If we ever need to modify the database schema or SQL queries, we only touch DAO classes without altering GUI panels."

Q4: How did you ensure ACID properties in financial transactions?

Answer: "In FeeDAO.java, we disable autocommit (conn.setAutoCommit(false)). We validate the payment against the student's due balance. If valid, we update the ledger and call conn.commit(). If an invalid amount is entered, a custom FeeException is raised and conn.rollback() is executed, preserving database consistency."

Q5: What is the difference between checked and unchecked exceptions in Java?

Answer: "Checked exceptions (like SQLException and our custom FeeException) extend java.lang.Exception and are enforced at compile time with mandatory try-catch or throws clauses. Unchecked exceptions extend RuntimeException and occur during execution (like NullPointerException)."

6. Post-Presentation Workflow & MySQL Handling

MySQL & XAMPP State After Finishing
  • Should you stop MySQL after showing the project? Yes. When you are done for the day or closing your laptop, simply open the XAMPP Control Panel and click Stop on MySQL and Apache.
  • Will closing MySQL or shutting down the computer erase records? No. MySQL commits and flushes all records to persistent disk storage (.ibd data files). All newly added students, fee payments, and attendance logs remain permanently saved.
  • Starting again for the next demonstration: Open XAMPP Control Panel ➔ click Start on MySQL ➔ double-click run.bat.
